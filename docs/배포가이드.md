# 배포 가이드 (GitHub Pages + Cloudflare Workers, 무료)

구성: **웹(React 정적 파일) → GitHub Pages**, **API(Hono) → Cloudflare Workers**. API 키는 Workers 시크릿에만 저장합니다.

## 0. 준비 (Windows PowerShell 기준)
- Node.js 22 LTS 설치(https://nodejs.org), Git 설치 후 **새 PowerShell 창**을 엽니다. 관리자 권한/`C:\WINDOWS\system32`는 쓰지 말고 일반 폴더에서 작업하세요.
- 구버전 PowerShell(5.x)은 `&&`를 지원하지 않으므로 **명령을 한 줄씩 실행**합니다.
```powershell
cd $HOME\Documents
git clone https://github.com/JUNGHWAN12/school_prop
cd school_prop
git checkout claude/wonderful-brown-hi5a97   # main에 병합 전이라면
```

## 1. API 배포 (Cloudflare Workers)
1. Cloudflare 가입(무료) 후 아래를 한 줄씩 실행 (브라우저가 열려 로그인/허용)
   ```powershell
   cd server
   npm i
   npx wrangler login
   ```
2. 시크릿 등록 (값은 프롬프트에 직접 입력, 채팅·커밋에 붙여넣지 말 것)
   ```bash
   npx wrangler secret put UPSTAGE_API_KEY
   npx wrangler secret put GEMINI_API_KEY
   ```
3. `server/wrangler.toml`의 `ALLOWED_ORIGIN`을 본인 GitHub Pages 출처로 수정 (예: `https://<계정>.github.io`, 경로 제외)
4. `npm run deploy` → 출력되는 주소(`https://edu-approval-api.<서브도메인>.workers.dev`)를 메모
5. 확인: `curl https://<워커주소>/api/health` → `{"ok":true}`

(선택) GitHub Actions로 배포: 저장소 Secrets에 `CLOUDFLARE_API_TOKEN`(Workers 편집 권한), `CLOUDFLARE_ACCOUNT_ID` 등록 후 Actions 탭에서 "Deploy API to Cloudflare Workers" 수동 실행.

## 2. 웹 배포 (GitHub Pages)
1. 저장소 **Settings → Pages → Source: GitHub Actions** 선택
2. **Settings → Secrets and variables → Actions → Variables**에 `API_BASE_URL` = 위 4번의 워커 주소(끝에 `/` 없이)
3. `main`에 `web/**` 변경이 푸시되면 자동 배포됩니다. (수동: Actions → "Deploy web to GitHub Pages" → Run)
4. 주소: `https://<계정>.github.io/<저장소명>/`

## 3. 운영 점검
- 로그인 없는 공개 API라 아래 "남용 방지" 설정을 반드시 확인하세요.
- 비용 통제: Upstage/Google 콘솔에서 월 한도 설정, 결제수단 미등록. Workers 무료 한도(요청 수·CPU 시간)는 Cloudflare 대시보드에서 확인
- 실시간 로그: `npx wrangler tail` (견적서 본문·개인정보는 로그에 남기지 않음)
- 장애 시: AI 분석이 실패해도 품목 직접 입력으로 품의문·엑셀 생성 가능

## 4. 남용 방지 설정

### 4-1. Cloudflare Turnstile (사람 확인, 무료) — 권장
1. Cloudflare 대시보드 → **Turnstile** → **위젯 추가**
   - 위젯 이름: `edu-approval`
   - 호스트 이름: `junghwan12.github.io` (로컬 시험도 하려면 `localhost` 추가)
   - 위젯 모드: **관리형(Managed)**
2. 생성 후 표시되는 **사이트 키**(공개)와 **시크릿 키**(비밀)를 확인합니다.
3. 시크릿 키를 Worker에 등록 (PowerShell, `server` 폴더에서). 값은 프롬프트에 직접 입력하세요.
   ```powershell
   npx wrangler secret put TURNSTILE_SECRET_KEY
   ```
   또는 Cloudflare 대시보드 → Workers → `edu-approval-api` → Settings → Variables and Secrets에서 **시크릿**으로 추가합니다.
4. 사이트 키를 GitHub 저장소 **Settings → Secrets and variables → Actions → Variables**에 `TURNSTILE_SITE_KEY`로 등록
5. Actions 탭 → "Deploy web to GitHub Pages" → Run workflow (웹을 다시 빌드해야 사이트 키가 반영됩니다)

주의: 시크릿(서버)만 먼저 등록하고 사이트 키를 아직 반영하지 않으면 웹이 토큰을 보내지 못해 **분석이 모두 거부**됩니다. 반드시 4~5단계까지 끝낸 뒤 확인하세요. 시크릿을 지우면 Turnstile 검증이 꺼집니다.

### 4-2. 전역 호출 카운터 (Durable Object)
- `wrangler.toml`의 `[[durable_objects.bindings]]`/`[[migrations]]`가 처음 배포할 때 자동으로 `Limiter`를 만듭니다. 추가 설정은 필요 없습니다.
- 하루 전체 `DAILY_CALL_LIMIT`(기본 200), IP별 `DAILY_PER_IP_LIMIT`(기본 50)이며 한국 시간 자정에 초기화됩니다. 값은 `wrangler.toml`에서 바꿉니다.
- 첫 배포 후 Cloudflare **Builds → History** 로그에서 마이그레이션 오류가 없는지 확인하세요. 오류가 나면 이전 버전이 그대로 서비스되므로 서비스는 중단되지 않습니다.
- Durable Object 호출이 실패하면 서버 메모리 카운터로 대체되어(정확도는 낮아짐) 서비스는 계속됩니다. 로그에 `limiter_error`가 반복되면 점검이 필요합니다.

### 4-3. 비상 대응: 킬 스위치
남용이 의심되면 `server/wrangler.toml`의 `# DISABLE_EXTRACT = "true"` 줄 앞의 `#`을 지우고 `main`에 병합하세요(GitHub 웹에서 파일 편집 → 커밋하면 됩니다). 자동 배포 후 AI 분석이 중지되고 "품목을 직접 입력해 주세요" 안내가 표시됩니다(수동 입력으로 품의문·엑셀은 계속 만들 수 있습니다). 해소되면 다시 `#`을 붙입니다.

### 4-4. 공급자 쪽 한도 (가장 확실한 최후 방어선)
- Upstage 콘솔(https://console.upstage.ai)에서 이 키의 잔여 크레딧·사용량·한도를 확인하고, 설정 가능하면 월 상한을 둡니다.
- Google AI Studio에서 무료 티어(결제 미연결) 프로젝트의 키를 사용합니다.
- 월 1회 사용량을 점검합니다.

### 4-5. 로그 확인
`npx wrangler tail`로 실시간 로그를 봅니다. 분석 성공(`extract`), 실패(`extract_failed`), 카운터 오류(`limiter_error`)가 기록되며 견적서 본문·개인정보는 남지 않습니다.
